# Registry query/SP/view

Setiap query, stored procedure, dan view yang dipanggil aplikasi baru dicatat di sini dengan hasil ukur. Aturannya ada di [`PERFORMANCE.md`](PERFORMANCE.md). Waktu diukur terhadap DB dev lama (data berukuran produksi: 760.909 rekening, `SCALLUSERLOG` ±1 juta baris) dari mesin pengembang, jadi nilainya sebagai pembanding relatif, bukan janji produksi.

Keputusan: **Pakai** (apa adanya), **Tulis ulang** (query setara yang lebih cepat/berbatas, divalidasi terhadap aslinya), **Tunda** (belum dipakai), **Hindari**.

| `SP_AUDITTRAIL` (@TEMPORARYID, @USERID) | persetujuan | Pakai, **satu transaksi dengan penulisan `SCALLUSER`** | Menyalin ajuan ke `AUDITTRAIL`; untuk Insert memberi password awal (`LOGINPARAM.DEF_PWD`) dan masa berlaku; untuk Delete memindahkan rekening user itu ke upliner di `LOSPANINCOLLECTION.dbo.LOAN_MASTER` (nama DB tertanam di SP); lalu menghapus ajuan. |
| trigger `INS_USER`/`UPD_USER`/`DEL_USER` pada `SCALLUSER` | menjaga `TEMP_DOWNLINE` | Pakai | Mengasumsikan penulisan satu baris; `UPD_USER` menghitung ulang bawahan setiap `UPDATE` yang menyebut `SU_UPLINER`. |
| `VW_SCALLUSER` (`SELECT *`) | daftar user | **Diganti** SELECT kolom eksplisit | Layar lama membaca seluruh kolom, termasuk `SU_PWD` (hash), ke browser. Baru: hash password tidak pernah dibaca aplikasi di layar ini. |
| `VW_SCALLUSERPENDING` | daftar ajuan | Pakai + ringkasan perubahan (`FieldValueBefore` vs `FieldValue`) | 7 subquery berkorelasi per baris; ajuan biasanya <100 baris. |
| `UPDATE SCALLUSERFLAG SET SU_LOGON/SU_REVOKE = 0`, `SU_PWD = DEF_PWD` | buka kunci / cabut revoke / reset password | Pakai, **dicatat di log** + hak Maker | Layar lama tanpa pencatatan. Buka kunci juga melepas sesi di server baru (`ReleaseAll`). |

| `SCALLGROUP` (+ `VW_SCALLGROUPPENDING`) | ajuan group (Insert/Update/Delete) | Pakai lewat mesin ajuan yang sama (`ParameterEngine`) | Persetujuan menulis `SCALLGROUP` + `SP_AUDITTRAIL` dalam satu transaksi; hapus group juga menghapus `GRPMENUX`-nya. Group yang masih punya user tidak bisa dihapus (dicek saat mengajukan **dan** saat menyetujui); group sendiri tidak bisa diajukan hapus. |
| `GRPMENUX` (akses menu per group & modul) | editor akses menu | Pakai, **atomik** (`DELETE` + `INSERT` dalam satu transaksi), induk menu otomatis ikut | **Layar lama menyimpannya langsung oleh maker tanpa approval** (callback pohon menu menghapus lalu mengisi `GRPMENUX`). Dipertahankan agar paritas, tetapi: hanya Maker (diperiksa di server), tercatat di log, menu divalidasi terhadap `RFMENUX` modul itu, dan hak Maker/Approval Maintenance milik group sendiri tidak boleh dicabut. Cache menu dan daftar modul group dibuang di server ini; instance lain baru ikut setelah ≤5 menit. **Akses modul = punya minimal satu menu modul itu** (`VW_GRPACCESSMODULE`), jadi mengosongkan semua menu mencabut akses modul. |
| `PARAMETERSYSTEM` | daftar parameter di menu Maker/Approval | Pakai | Hanya menentukan entri yang tampil; halaman tujuan dipetakan dari nama berkas tautan lama. Group Treatment (`GRPACCESSTREATMENT`, modul 60) belum dimigrasi dan tampil sebagai "Belum dimigrasi". |

| `PARAMETERSYSTEM` (SETID `GEN`/`PROC`/`USER`) + `PARAMETERSYSTEMFIELD` | editor parameter generik (±50 tabel `RF*`, Group Treatment) | **Diganti**: nama tabel/kolom hanya dipakai bila ada di metadata **dan** di `sys.columns`, lalu diberi kurung siku; nilai = parameter bertipe | Layar lama menyusun SQL dari teks dan membaca nilai dari kontrol web. Tipe kolom diambil dari DB (bukan `FIELDTYPE`, yang tidak terisi di 384 baris). Tabel keamanan/metadata (`PARAMETERSYSTEM*`, `SC*`, `GRPMENUX`, `RFMENUX`, `RFMODULE`, `LOGINPARAM`, `AUDITTRAIL*`) **tidak bisa diedit** dari editor ini walau tercantum — sebelumnya `PARAMETERSYSTEM`/`PARAMETERSYSTEMFIELD` bisa diedit lewat set PROC, artinya maker bisa memperluas apa yang bisa diedit. |
| `FIELDREFF` (SQL dropdown di metadata; 17 baris) | dropdown lookup | Dijalankan hanya bila berupa `SELECT kolom[, kolom] FROM tabel [WHERE ...] [ORDER BY ...]` tanpa `;`, komentar, atau perintah lain; di-cache 5 menit; maks. 2.000 opsi | Layar lama mengeksekusi apa pun yang ada di kolom ini. Ke-17 baris yang ada lolos pemeriksaan. |
| tabel tanpa kolom kunci di metadata (mis. `RFSEX`) | editor parameter | **Hanya-baca** dengan penjelasan | Tanpa kunci, "ubah/hapus" tidak bisa menunjuk satu baris; layar lama tetap menyimpan dan bisa menggandakan baris. Begitu pula kunci `identity`/tipe tak didukung. |
| hapus pada parameter generik | persetujuan Delete | Sama dengan lama: `ACTIVE = 0` bila tabel punya kolom `ACTIVE`, selain itu `DELETE` | `DELETE` dijaga `RAISERROR` bila bukan tepat satu baris; semuanya satu transaksi dengan `SP_AUDITTRAIL`. |
